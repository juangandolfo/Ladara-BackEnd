# User Module

## Overview

The User module manages user accounts and identity. Users are created via Google OAuth and can have admin privileges. The module provides basic CRUD operations for user management and role assignment.

## Files

- `user.entity.ts` - User database schema
- `user.service.ts` - User business logic

## Entity: User

**Table**: `users`

| Field | Type | Constraints | Purpose |
|-------|------|-------------|---------|
| `id` | UUID | PK, NOT NULL | Unique user identifier (from Google) |
| `name` | VARCHAR | NOT NULL | User's display name |
| `isAdmin` | BOOLEAN | Default: false | Admin role flag |

### Example User

```json
{
    "id": "112105191225396162872",
    "name": "John Doe",
    "isAdmin": false
}
```

## User Creation

### First User Advantage
When a user authenticates via Google OAuth:

1. **First User**:
   - Automatically assigned `isAdmin = true`
   - Can manage products, discounts, and orders
   - Created when user count = 0

2. **Subsequent Users**:
   - Created with `isAdmin = false`
   - Can only browse products and manage their cart
   - Cannot access admin endpoints

### ID Assignment
User ID comes directly from Google OAuth profile:
- Format: Google's numeric user ID (string)
- Example: `"112105191225396162872"`
- Guaranteed unique per Google account

## UserService

### Methods

#### `getEntityById(id: string): Promise<User | null>`

Retrieve user by ID.

**Parameters**:
- `id` - User UUID (Google ID)

**Returns**: User object or null if not found

**Usage**: Used in auth middleware to fetch user from JWT token

**Example**:
```typescript
const user = await userService.getEntityById("112105191225396162872");
// Returns:
// {
//     id: "112105191225396162872",
//     name: "John Doe",
//     isAdmin: false
// }
```

## User Fields Explained

### `id` (UUID)
- Primary key
- Generated by Google OAuth
- Unique identifier for each Google account
- Never changes for same Google account
- Format: String representation of Google's user ID

### `name` (VARCHAR)
- User's display name
- Sourced from Google profile (displayName)
- Can be updated (currently no endpoint, but possible)
- Example: "John Doe", "Jane Smith"

### `isAdmin` (BOOLEAN)
- Role flag for access control
- Default: `false`
- Set to `true` for first user only
- Controls access to:
  - Product management (create, update, delete)
  - Discount management
  - Order completion
  - User management

## Admin Capabilities

Users with `isAdmin = true` can:

### Product Management
- Create products
- Update product details
- Delete products (soft delete)
- Permanently delete products
- Restore deleted products
- View all products
- View deleted products

### Discount Management
- Create discounts for users
- Update discount details
- Delete discounts
- List all discounts
- List deleted discounts

### Order Management
- Mark orders as completed/prepared
- View all orders (admin dashboard)

### User Management
- View all users (future enhancement)
- Modify user roles (future enhancement)

## Authentication Flow with Users

```
1. User clicks "Login with Google"
   ↓
2. Redirected to Google consent screen
   ↓
3. User grants permission
   ↓
4. Google redirects to /auth/google/callback with profile
   ↓
5. AuthService.handleGoogleUser(profile)
   a. Check if user exists by Google ID
   b. If not exist:
      - Count users in DB
      - If count = 0: set isAdmin = true
      - Else: set isAdmin = false
      - Save user
   c. Generate JWT token with user.id
   d. Return user + token
   ↓
6. Frontend stores token
   ↓
7. Frontend adds token to Authorization header for API calls
   ↓
8. AuthMiddleware verifies JWT and loads user via UserService
```

## User Relationships

### Users in Other Modules

**Orders**: One-to-Many
- User can have multiple orders
- Used for filtering user's orders/cart

**Discounts**: One-to-Many
- User can have multiple discounts
- Used when applying discounts to prices

**Auth**: One-to-One (implicit)
- Each JWT token represents one user
- Token contains user.id

## Security Considerations

### No Password Storage
- Users authenticated via Google OAuth
- No passwords stored in database
- More secure than password-based auth

### User ID Privacy
- Google ID is used (numeric string)
- Not directly exposable to frontend for privacy
- Used internally for relationships

### Admin Role Sensitivity
- Only first user should be admin
- Consider implementing admin assignment endpoints
- Audit changes to isAdmin field

## Example Scenarios

### First User Registration
```
Database: empty
User signs up via Google (John Doe)
→ UserService creates user
→ Sets isAdmin = true
→ John can now access admin endpoints
```

### Second User Registration
```
Database: has 1 user (John)
User signs up via Google (Jane Doe)
→ UserService creates user
→ Sets isAdmin = false
→ Jane cannot access admin endpoints
```

### Repeat Login
```
User logged in before (John Doe)
User logs in again via Google
→ UserService finds existing user
→ isAdmin remains true
→ Generates new JWT token
→ No duplicate created
```

## Related Concepts

## Error Scenarios

### User Not Found
```
JWT contains valid token but user deleted from DB
→ Auth middleware returns 403
→ "Forbidden: User not found"
```

### First User Not Admin
```
Database corrupted or manually modified
→ First user has isAdmin = false
→ Cannot access admin endpoints
→ Manual database correction needed
```
